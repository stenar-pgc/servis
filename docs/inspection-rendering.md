# Recreated inspection reports

The HTML results use a responsive web interface. PDF reports use code and static assets reconstructed from the supplied Excel workbook; generating a PDF never opens an XLSX file. Excel uploads remain supported by the separate deterministic importer.

The layout definitions describe cell geometry, merged cells, colors, fonts, borders, image positions, chart series and conditional color scales. The browser uses separate responsive charts and tables for working with measurements. The backend draws them with TCPDF and embeds the supplied Roboto/Roboto Slab fonts. The app’s small formula interpreter is implemented in both JavaScript and PHP and receives the trusted JSON definitions and saved values. It supports only the functions used in this version of the workbook. Uploaded formulas are never evaluated.

The backend already declares TCPDF in Composer; run `composer install --no-dev` if it is not installed. Deploy `controllers/class.servis.php` and the complete `conf/inspection/` directory together. The renderer needs no office application, system fonts, shell/process permission, Node or external conversion service. Existing PHP extensions are checked by Composer.

**Equipment-specific views:** `Jadralno padalo` uses the wing measurements and its 27 workbook-based report variants. `Reševalno padalo` uses its own canopy/lines/riser/container checklist, 1–5 condition rating and deployment notes, with SL/EN/DE certificates reconstructed from the supplied reserve PDFs. Harnesses and other equipment have a general service record with work performed, condition, named measurements/units and notes; they do not receive wing charts or a wing airworthiness declaration. Existing PDF uploads/previews remain available for every type.

When a reserve has no structured record, the backend reads recognized fields from its existing certificate PDF with Composer’s `smalot/pdfparser`. This is a draft: viewing it writes nothing. Saving explicitly preserves the original PDF as an immutable source with field/page/hash evidence in the existing inspection tables. Missing or unrecognized values stay blank. The imported order’s creation date is not substituted for the certificate date. Deploy the updated Composer files and run `composer install --no-dev` for PDF text extraction; rendering itself uses the existing TCPDF dependency.

Matching F-layout report references determine the preferred F view for historical imports whose stored report selection was generic. This selection does not rewrite measurements or change equipment identity.

The 27 report variants retain their original artwork, text and chart references. Two-page reports have explicit section boundaries. Workbook notes in B37 are excluded from all report outputs. Signature/stamp artwork is stored privately on the backend and included only by authenticated report-generation code. The unfinished Hitri pregled variant stays outside the normal selector. The older frozen English F sheet is connected to live data; F and standard measurements remain separate stored layouts, with explicit F bindings for older shared report headers.

The report can be previewed privately, then attached to the existing service/equipment documents. Rendering does not send email. The complete workbook audit and trusted mappings remain in `conf/inspection/audit.json` and `manifest.json`. An authoritative technician export is still useful for comparing exact typography and printer pagination.

The local, unpublished `scripts/inspection-layout.py` helper is a one-time development extraction/reconstruction tool. It sanitizes source inputs and formula caches before writing the static layout definitions; Python and the reference XLSX are not runtime dependencies. The backend `template.xlsx` has been removed.

The PDF geometry was checked against real imported reports. It uses the workbook’s Roboto column metrics, print extent and section boundaries, with no added outer margins. Dates and small grid values stay on one line; validity text follows spreadsheet comparison rules for labels such as `100 UR`. The airfoil artwork is reconstructed as a vector to avoid transparent-PNG color shifts.

Local visual review uses the private `servis-import/servis-import.sql` dataset plus the Niceclouds user dump in an isolated MariaDB instance. The local PHP review server proxies Vite and runs the actual controller/database wrapper; API response data is not mocked. The review copy disables all email delivery. Private data, credentials, review scripts and screenshots remain ignored and are not deployment assets.
