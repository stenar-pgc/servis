Inspection workbook audit and implementation

Reference: 26-P241 Nova Ion 5 Light XS.xlsx. 41 visible sheets, 13,492 formulas, 49 charts and 17 embedded image assets. No VBA project, external workbook links, named ranges or saved print areas were present. DrawingML assets are retained directly; saving this file through openpyxl loses image information and is deliberately avoided.

Input and calculation map

  • Vnos podatkov: B1 inspection date, B2 existing customer name, B3 report counter, B4 previous inspection, B5–B10 existing equipment identity/certification/manufacture date, B11 validity choice, B12 flight-hour limit, B14–B21 porosity at positions 0–7 m, B23–B31 check flags and visual ratings, B33–B36 customer report notes, B37 private workshop notes.
  • dolžine vrvic: B2:G24 nominal A–E/Br lengths; J2:Q5 branch counts. Lower scratch areas contain unrelated historical manufacturer data and are not active input. Original source bytes retain those scratch areas for traceability.
  • A: C4:H26 right and I4:N26 left readings; AB28–AB32 offsets/measurement attachment; AG30:AL52 per-line corrections. Normal deviation = measured − nominal − riser length + equalizing value + attachment offset + individual/riser corrections. Brake lines use their separate offset. Right-minus-left deviations supply symmetry.
  • trimanje: derives adjusted readings from A, individual corrections and Z36:AA50 branch corrections. kontrolna meritev stores independent verification readings. B selects A when trim is “ne”, the control sheet when control is “da”, otherwise the calculated trim result. No uploaded formulas are executed.
  • F layouts: nominal A–F/Br values, right C:I and left J:P readings, AF30:AF34 settings and AK32:AQ56 corrections. Up to 25 rows are preserved independently from the standard layout. Both layouts in the supplied workbook contain data: the app never guesses that the F readings belong to the current wing.
  • Strength: the SL/EN strength sheets each contain three test rows (level, name, material, minimum 8g/10g and breaking load); they are imported separately rather than guessed to be interchangeable.
  • Condition: porosity means/minimum/three worst values; capped average at 350 seconds; visual ratings divided by 10; age contribution (7295−days)/7295; piecewise equalizing contribution; porosity-dependent weight (11−10×porosity score). The implementation preserves the workbook formulas and leaves undefined calculations blank.

Triggers, validations and color

Seven validations in the main input sheet reference criteria lists: manufacturer, size, certification, validity, hours, yes/no checks and ratings 1–10. Measurement/trim sheets have additional correction/branch choices. The original red–green–blue line heatmap uses −40/0/+40 mm in reports (−20/0/+20 on input/calculation sheets). Charts use cyan for the ±10 mm band and orange beyond it. The app preserves input cell fills, supports decimal commas, row/column traversal, batch paste, Enter/Tab and explicit laser-unit conversion.

The version history mentions a 2025-11-20 cursor-advance script and a proposed reset/increment trigger. Their code is absent from the XLSX. Keyboard-like laser input is implemented and simulated in browser tests; a physical laser or proprietary serial/Bluetooth protocol has not been tested.

Storage and import contract

servis_inspections stores one versioned inspection per existing order/equipment pair, its date, number, report sheet and optimistic revision. servis_inspection_values stores typed values with metric, phase, side, axis, position, unit and original sheet/cell. servis_inspection_sources retains immutable uploaded bytes, filename, SHA-256 and importer. Source hash/page/evidence columns accommodate later PDF extraction. Existing users, customers, orders, equipment and private documents are reused; only certification/manufactured columns extend equipment.

Import preview makes no writes. It validates the known sheet names, identifying labels, ZIP/XML bounds, types and fixed cell mapping. Formula-bearing input cells are rejected. Changed calculation formulas are disclosed; uploaded formula caches are not authoritative. Apply re-parses the same source, checks its preview hash and current revision, then commits readings/source atomically. Identical files do not replace later edits. Customer names never link/create accounts. An explicit equipment-update choice controls metadata replacement. Existing PDFs are preserved.

Rendering and source discrepancies

  • PDFs use a private sanitized copy of the original OOXML, preserving artwork, drawings, chart definitions, merged cells, borders and fonts. Rendering requires LibreOffice, PHP ZIP/DOM/GD/proc_open, Roboto and supplied Roboto Slab fonts. Temporary files have private permissions and are removed.
  • Google arithmetic aliases and date coercion require normalization for LibreOffice. Google SPARKLINE fallbacks become live data bars. Embedded percentage images are regenerated. Narrow date cells shrink to fit; text layout otherwise retains the original styles. The frozen English F report is reconnected to live header fields; legacy F headers are bound to F input.
  • Some old report-number formulas hard-code a prior year or format the number as a date; rendering derives the year/reference from the inspection. The legacy “Hitri pregled” sheet is marked unfinished by its author and is omitted from the normal report selector.
  • The prose criteria sheet and executable score formulas have different thresholds. The app follows the actual formulas and does not claim a new inspection standard. The source also contains formula edge cases and mixed historical layouts; technicians must review results and the selected layout.
  • The original workbook has no print areas. The app defines A4 ranges for each report and one/two-page output. Artwork is preserved, but an authoritative PDF exported by the technician is still needed for an exact print-layout comparison across renderers.
  • Existing declarations, authorized-person name and signature artwork are retained. Preview is private; the technician explicitly attaches the report to the order for customer access. No email is sent by import/save/render.
